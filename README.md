一个**可复现、可审计**的英超赛果概率预测器。不做"准确率 62%"式的宣传，只回答一个问题：
**在数据、指标和基准都摆在桌面上的时候，模型离博彩收盘赔率还有多远？**

答案是：**还差 0.0209 log loss，而且这个差距在统计上显著。** 这个仓库把这件事当作主要结论写出来，而不是藏起来。

---

## 先讲人话：这个项目在做什么

给每场英超比赛算三个概率（主胜 / 平 / 客胜），然后拿它去和博彩公司的价格对账。
重点不是"猜得准"，而是**输得明白**。

**为什么难。** 一场球平均 2.6 个进球，一次折射就能改写结果；平局占 23%，却几乎没有可靠信号；
三分类下"准确率"几乎没有意义——一律猜主胜也能到 45%，但那是废的。

**做法分五步：**

1. **数据** —— 13 个赛季、4,630 场比赛，每场一行：比分、射门、射正、红黄牌，以及各家博彩公司的初盘和收盘盘。
2. **特征** —— 把球队状态量化成数字：Elo 等级分（类似围棋段位，赢球加分、输球扣分、主场 +60、赛季间向均值回落 1/3），
   加上最近 5 场的进球/失球/射正（越近权重越高）、休息天数、赛季进度。
   铁律：**只能用开赛前就已经知道的信息**。
3. **模型** —— 五个模型并存，各干各的。
4. **评估** —— 主指标是 **log loss**：你说 90% 会发生，结果没发生，罚得很重；说 45%，罚得轻。
   它同时惩罚"错"和"假装确定"，所以墙头草和莽夫都拿不了高分。
5. **防作弊** —— 预测某赛季时只许用该赛季开赛前的数据（walk-forward）；超参在测试集之前的老赛季上调；
   两个测试专门验证"删掉未来数据，过去的特征一个数都不许变"；最后和**博彩公司收盘价**比，而不是和自己比。

**五个模型分别是什么：**

| 模型 | 大白话 |
| --- | --- |
| 常数基线 | 永远报 43% / 24% / 33%，用来卡下限 |
| Elo + 逻辑回归 | 两队分差 → 一条平滑的概率曲线 |
| **Dixon-Coles** | 每队拆成"进攻力/防守力"，算出期望进球，再从泊松分布**掷骰子掷出比分**；唯一能给出完整比分分布的模型 |
| 梯度提升树 | 几百棵小决策树互相纠错 |
| 融合 | 按上两季战绩给前三者加权 |

**技术栈**：Python + pandas/numpy（数据）、scipy（优化 Dixon-Coles 参数）、scikit-learn（回归与树模型）、
matplotlib（图表）、parquet（缓存）、GitHub Actions（每周自动重算）、GitHub Pages + 原生 JS（前端现场算泊松分布）。

**不是深度学习项目。** 没有神经网络、没有大模型，所有复杂度都在"怎么诚实地评估"，不在"怎么把模型做大"。

> 一句话：**我不知道怎么赢过庄家，但我知道自己输在哪、输多少、以及为什么。**

## 核心结论

1. **模型打不过收盘赔率。** 3,044 场样本外比赛上，融合模型 log loss `0.9767`，去除抽水后的收盘价 `0.9558`，差距 `+0.0209`（95% bootstrap CI `+0.0147` ~ `+0.0271`，不含 0）。
2. **主场优势被市场定价得比模型更好。** 准确率上模型 53.0% vs 市场 55.0%，但准确率从来不是重点——概率校准才是。
3. **模型在平局上系统性偏保守。** 校准图右侧那个点（预测 `P(draw)≈0.30`，实际只有 `0.23`）是这个项目里最稳定的偏差。
4. **堆叠不可估。** 用一季 380 场去估三个模型的权重，结果全在噪声里：等权 `0.9770`，调权 `0.9767~0.9803`。所以默认用"向等权收缩 50%"的固定规则，而不是挑一个好看的数。

## 校准层：差的是信息，不是自信

一个必然会来的质疑：**你是不是没做校准就下结论了？**

做法：给每个模型加一个温度参数 `T`（`pᵢ → pᵢ^(1/T)` 归一化），在**上一季**的样本外预测上拟合，
绝不接触被测赛季——和堆叠权重同一条因果约束。

<!-- CALIB:START -->

| 模型 | log loss | + 温度 | 变化 | T 中位数 |
| --- | --- | --- | --- | --- |
| Blend (Elo + DC + GBDT) | 0.9767 | 0.9798 | +0.0031 | 1.00 |
| Elo + softmax | 0.9788 | 0.9805 | +0.0017 | 1.00 |
| Dixon-Coles | 0.9941 | 1.0030 | +0.0089 | 1.03 |
| Gradient boosting | 0.9911 | 0.9906 | -0.0006 | 1.14 |

温度在**上一季**的样本外预测上拟合，绝不接触被测赛季。T 中位数在 1.00–1.14 之间移动：融合与 Elo 基本是 1.00，唯一偏乐观的是梯度提升（1.14，校准后确实降了 0.0006），但它的整体水平太差，校准救不回来。**没有模型的校准被温度明显改善。**

**Brier 分解**（Murphy）：`Brier = 可靠性 − 分辨率 + 不确定性`

| 预测 | 可靠性 ↓ | 分辨率 ↑ | Brier |
| --- | --- | --- | --- |
| 收盘价 | 0.0012 | 0.0786 | 0.5681 |
| 融合 | 0.0016 | 0.0660 | 0.5812 |
| 融合 + 温度 | 0.0014 | 0.0628 | 0.5841 |

读法：两者的**可靠性几乎相同**（0.0016 对 0.0012），差距几乎全部来自**分辨率**（0.0661 对 0.0786）。也就是说，模型不是过度自信，而是**知道得更少**——它没有比庄家更差的校准，只有更少的信息。这解释了为什么温度校准救不了差距，也指出了唯一有意义的方向：加信息（xG、伤停、欧战赛程），而不是调概率。

![校准研究](reports/calibration_study.png)

<!-- CALIB:END -->

结论就藏在那两张表里：温度几乎不动（融合与 Elo 的 T 中位数是 1.00，唯一偏乐观的 GBDT 是 1.14，
校准后确实降了 0.0006，但它本来就太弱，救不回来）；而 Brier 分解显示**两家的可靠性几乎相同**，
差距全在分辨率。换句话说：**模型不是不会报概率，是知道得更少。**

这解释了为什么调参数救不了差距，也把路线图钉死在"加信息"上——xG、伤停、欧战赛程，
而不是继续在模型结构里找 0.001。

## xG 消融：−0.0014，方向对但很薄

"没有 xG"是这类项目最常被点名的短板——射正只是"创造机会"的粗糙代理。于是补上 Understat
（2014-15 起全覆盖，13 季 4,635 场，合并后覆盖率 **100%**），然后做一次严格消融：
训练窗口、测试比赛、超参数全部相同，唯一变量是树模型有没有看到 xG 块
（近 5 场 xG 进/失、xG 差、射门转化偏差）。

| 变体 | log loss | 变化 |
| --- | --- | --- |
| GBDT（无 xG） | 0.9911 | — |
| GBDT + xG | 0.9896 | **−0.0015** |
| 等权融合（无 xG） | 0.9770 | — |
| 等权融合 + xG | 0.9756 | **−0.0014** |

配对 bootstrap：`−0.0014`，95% CI `[−0.0029, +0.0000]`，P(更好) = 0.97。
9 个赛季里 6 个改善，但 **2021-22 一个赛季就贡献了 −0.0058**，另外三个赛季反而变差。

![xG 消融](reports/xg_ablation.png)

> 消融里用的是等权融合，所以基线 0.9770 与主榜单的 0.9767（收缩后权重）略有差异——这是刻意的，
> 为的是让"加不加 xG"成为唯一变量。

**结论：有效，但很薄。** 主模型保持不依赖 xG——为了 0.0014 每周去依赖一个会被 Cloudflare 拦的抓取器，
不划算。xG 以可选依赖的形式保留：

```bash
pip install -e ".[xg]"
pythia fetch --xg      # 抓 13 季 Understat xG
pythia build           # 特征表自动多出 xG 块
pythia ablate          # 复现上面这张表
```

真正值得记的是这个方向感：**差距不在"少一个公开特征"，而在市场独享的信息**——伤停、首发、
轮换。公开数据能补的基本都补完了，这 0.02 大概就是"知道谁今天不能上"的价钱。

## 伤停数据：一条走到尽头的路，和一根埋下的线

既然结论指向"市场独享的阵容信息"，那就去拿。这是整个过程里最有意思的一段，因为它**失败的原因不是技术**。

### 第一步：找到源头，看起来完美

FPL 官方 API 的 `bootstrap-static` 给出 669 名球员的实时状态：

```
status: a 可用 / d 存疑 / i 伤停 / s 停赛 / u 不可用
chance_of_playing_next_round: 0-100
news: "Knee injury - Expected back 15 Nov"
```

本轮（GW8）669 人里有 **200 人不是完全可用**。这正是我们想要的信号。

### 第二步：问一个致命的问题——能回测吗？

不能。查单球员的 `element-summary/{id}`，逐轮 `history` 的字段是：

```
minutes, starts, total_points, expected_goals, ...
```

**只有赛后才知道的东西，没有任何一个字段记录"那一轮赛前他是不是伤停"。**

官方 API 只暴露"现在"，不暴露"当时"。没有历史快照 → 没有样本外 → 没有数字。
而任何用"现在伤停"去解释"过去比赛"的做法，都是穿越。

### 第三步：那还有什么能做

**从今天开始攒。**

每次刷新存一个 20 行的小快照（球队级、按赛季分钟加权），提交进仓库：

| 字段 | 含义 |
| --- | --- |
| `avail_score` | 可出场球员的赛季分钟 / 全队分钟，越接近 1 越健康 |
| `n_injured` / `n_doubtful` / `n_suspended` | 各类不可用人数 |
| `minutes_available` | 还在的"实际出场时间"，比人数更能反映损失 |

截至今日本轮，最惨的几家：

| 球队 | 伤 | 存疑 | 停 | 可用性 |
| --- | --- | --- | --- | --- |
| Leeds | 2 | 3 | 0 | 74.1% |
| Man United | 5 | 1 | 0 | 83.8% |
| Liverpool | 6 | 1 | 0 | 84.1% |
| Chelsea | 5 | 1 | 0 | 84.7% |

数据在 `data/fpl/`，由 Actions 每周追加一次，文件名带日期。一年后就有 50 多个时间点，
可以真正检验"某队可用性骤降 → 之后三轮的结果"，那才是可回测的特征。

### 一条副产物：队名又是坑

FPL 用的名字和 football-data 又不一样：`Spurs`、`Hull City`、`Ipswich Town`、`Coventry City`。
四个别名补进 `teams.py` 才连得上——**"60% 的工作量在队名映射上"这句话，这已经是第三次被验证了**
（football-data → Understat → FPL，三家三种写法）。

### 现在的态度

**它只用来展示，不进模型。** 理由和温度校准、xG 完全一致：
没经过样本外验证的东西，不进主榜。这不是保守，是这个项目唯一值得信的地方。

```bash
pythia fpl              # 看当前各队可用性
pythia fpl --snapshot   # 存一份今天的快照（Actions 每周自动做）
```

## 派生市场：大小球 2.5 —— 本该是结构模型的主场

前面所有实验都在 1X2 上。但 Dixon-Coles 产出的是**完整比分分布**，所以它天然能定价"总进球数"，
而任何基于 1X2 标签的分类器都不能。这本来应该是它的主场。

数据上有个门槛：football-data 从 **2019-20** 才开始有大小球赔率（2014-19 完全没有），
所以这是 7 个赛季、2,729 场的样本，不是 9 季。

| | log loss |
| --- | --- |
| Dixon-Coles | 0.6871 |
| 收盘价（去抽水） | **0.6738** |
| 常数基准 | 0.6894 |

模型对庄家：`+0.0134`（95% CI `+0.0064 ~ +0.0205`，P(更好)=0.00）。

![大小球 2.5](reports/ou_25.png)

**但真正扎心的是第三行**：模型只比"每个赛季都报同一个大球率"好 **0.0023**，
而庄家比常数好 **0.0156**。也就是说，庄家在大球上有真实的分辨力，我们几乎只有水平。

2023-24 是最惨的一季：实际大球率 **64.7%**，模型只给 48.3%（庄家 58.6%）。
试过按赛季进球水平缩放（`score_matrix(scale=...)`）：2023-24 从 0.7133 降到 0.6890，
但其他赛季被拖累，净效应落在噪声内，所以没有并入。

> 结论：**DC 的比分分布对"谁赢"够用，对"进几个"不够。**
> 1X2 的 0.021 差距在这里缩到 0.013，不是因为模型变强了，而是这个市场本身更难定价、庄家优势更小。

```bash

```

## 与其它"预测仓库"的区别

这类项目 90% 死在同一个地方，不是算法，而是**评估协议**：

| 常见做法 | 本项目 |
| --- | --- |
| 随机 KFold 交叉验证 | 严格 walk-forward：预测某赛季时，只许用该赛季开赛前的数据 |
| 准确率当主指标 | 以 log loss 为主，Brier / RPS 为辅，准确率仅作参考 |
| 没有基准 | 常数基线 + Elo + 单模型 + **博彩收盘价**，四条对照线全在 |
| 只报赢的那些 | 报全部 9 个赛季，包括输得更惨的 2020-21 和 2025-26 |
| 结论不可复现 | `pythia fetch && pythia report` 一条命令重建全部图表 |
| 无防泄漏测试 | `tests/test_leakage.py` 用"截断数据"和"篡改未来结果"两种方式钉死特征 |

那 4 条结论之所以可信，是因为代码里有一组测试专门防止我自己骗自己。

## 方法

### 数据

- **football-data.co.uk**：2014-15 至 2026-27 共 13 个赛季、4,630 场比赛，含比分、射门、射正、红黄牌，以及多家博彩公司的**初盘与收盘盘**。
- **Understat xG**（可选）：2014-15 起 13 季 4,635 场，合并覆盖率 100%，用于消融实验，不进入主模型。
- 收盘价来源按赛季自适应：2024-25 及以前用 Pinnacle `PS*`，2026-27 起 Pinnacle 列名改为 `PP*`，2025-26 因 Pinnacle 覆盖不足（仅 55%）自动退到 Bet365 收盘盘——**每行都记录了实际使用的盘口来源**，不假装全样本同源。
- 时区、队名（`Man United` / `Nott'm Forest` / `Sheffield United`）统一走 `src/pythia/teams.py` 的别名表，未知球队原样保留，不会静默丢失。

### 特征（全部为赛前可得）

近 5 场指数加权进球/失球/射正、休息天数、赛季内场次、升班马标记、Elo 差分（含主场优势 60 分、赛季间向 1500 回归 1/3、净胜球加权）。**滚窗一律 `shift(1)`**，积分榜只到上一轮。
装了 `[xg]` 之后还会多出近 5 场 xG 进/失、xG 差与射门转化偏差——但只有 `gbdt_xg` 用它，见上文消融。

### 四个模型

| 模型 | 说明 |
| --- | --- |
| `base_rates` | 训练窗口内主/平/客的频率。任何跑不赢它的模型都是噪声 |
| `elo_logit` | Elo 差分 → 多项逻辑回归。单特征、强正则，反而最稳 |
| `dixon_coles` | 双变量泊松 + 时间衰减（半衰期 540 天）+ 低比分修正 `ρ`，可导出完整比分分布 |
| `gbdt` | HistGradientBoosting，样本按同样半衰期加权 |
| `blend` | 前三者的线性池，权重来自**此前两季**并**向等权收缩 50%** |
| `market` | 去抽水后的收盘价（除水用比例法），不是模型，是尺子 |

Dixon-Coles 是唯一能直接给出"比分分布"的模型，所以比分热力图、赛季模拟都基于它：

### 评估协议

- **Walk-forward**：9 个测试赛季（2018-19 → 2026-27），每个赛季重新拟合，训练集随赛季推移增长。
- **De-vig**：`1/odds` 归一化，逐行记录用了哪个盘口。
- **显著性**：配对 bootstrap（2,000 次）给出 log loss 差的 95% 区间，而不是只报一个点估计。
- **超参不在测试集上调**：GBDT 的迭代轮数/叶子数是在 **2017-18**（测试集之前最后一个完整赛季）上选的，不是从 9 个测试赛季里挑的。

## 附录 B · 价值投注探针（研究用途）

一个自然的追问：**当模型和市场分歧很大时，模型是不是对的？** 用初盘价（开赛前可得）算边际、平注 1 单位：

| 最小边际 | 下注场次 | 占比 | 平注 ROI |
| --- | --- | --- | --- |
| 2% | 2,614 | 92.2% | −5.2% |
| 5% | 2,280 | 80.4% | −5.6% |
| 8% | 1,994 | 70.3% | −3.2% |
| 10% | 1,795 | 63.3% | −4.0% |
| 15% | 1,372 | 48.4% | −4.8% |
| 20% | 1,069 | 37.7% | −6.6% |

**每一档都亏。** 而且模型给出的"边际"中位数高达 14%，这本身就是答案：那不是价值，是模型在长尾上比市场更自信
（典型的热门-冷门偏差）。平均 CLV 几乎为 0，说明这些注单完全没有跑赢收盘线。

结论：**这个模型没有可下注的 edge。** 保留这一节是为了展示否证过程，不是因为能赚钱。

## 已知局限

- **xG 只有边际价值**：接入了 Understat 全套 xG 并做了消融，净收益仅 `−0.0014`（见上文），
  主模型因此保持不依赖它。射正数与 xG 的相关性已经很高，公开数据能给的基本给完了。
- **没有伤停、阵容、赛程密集度（欧战）**：这些信息市场有，模型没有。按上面的分解，
  这大概就是剩下那 0.02 的主要来源。
- **升班马**：英冠数据未纳入，新升班马只能靠"联赛平均 + 收缩"，前 5 轮误差最大。
- **平局**：三分类里最难的一类，目前的偏差见校准图。
- **单联赛**：刻意不扩到五大联赛，先把英超做对。
- **校准已经做过**：温度缩放没有改善（T 中位数 1.00），说明问题不在置信度。
